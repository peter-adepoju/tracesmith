HTML says what things are. CSS says what they look like. This week is about the second one, and about the gap between them — which is where a surprising share of UI bugs live.

You will not be writing much CSS on the job. You will be reading it, constantly, to answer one question: *why does this look wrong?*

## Three ways styles reach a page

```html
<!-- 1. A linked stylesheet. How real sites do it. -->
<link rel="stylesheet" href="/styles.css" />

<!-- 2. A style block in the document. -->
<style>
  h1 { color: navy; }
</style>

<!-- 3. An inline style attribute. -->
<h1 style="color: navy;">Orders</h1>
```

The third one matters to you for a specific reason: **inline styles beat almost everything else**. When a rule in the stylesheet refuses to apply, an inline style is the first thing to check. You will see this in the Styles panel as a rule at the very top of the list, winning.

## The anatomy of a rule

```css
h1 {
  color: navy;
  font-size: 2rem;
}
```

- **`h1`** is the **selector** — which elements this applies to.
- The braces hold the **declaration block**.
- **`color: navy;`** is a **declaration**: a **property** and a **value**, separated by a colon, ended with a semicolon.

That is the whole syntax. CSS is not a difficult language. What makes it hard is that many rules can target the same element, and working out which one wins is a genuine skill — tomorrow's lesson.

## Properties you will meet constantly

| Property | What it controls |
| --- | --- |
| `color` | Text colour |
| `background` | Background colour or image |
| `font-size`, `font-weight` | Text size and boldness |
| `margin` | Space outside the element |
| `padding` | Space inside the element |
| `border` | The line around it |
| `width`, `height` | Size |
| `display` | How it behaves in layout, and whether it appears at all |
| `position` | How it is placed |
| `color` on a parent | Inherited by children unless overridden |

## The one that causes the most confusion

```css
display: none;
visibility: hidden;
opacity: 0;
```

All three make something invisible. They are completely different, and knowing which you are looking at turns a vague bug into a precise one.

- **`display: none`** — the element is removed from the layout entirely. It takes no space. It is still in the DOM, so your test can find it, but a user cannot see or click it.
- **`visibility: hidden`** — invisible, but **still takes up its space**. You get a mysterious gap.
- **`opacity: 0`** — fully transparent, takes up space, and is **still clickable**. An invisible button that intercepts clicks is a genuinely nasty bug, and this is how it happens.

Switch between them and click where the button is. Watch which methods leave a gap, and which one still catches your click.

## Why the same element can be styled many times

A page loads one or more stylesheets, each with hundreds of rules. A single `<button>` might be targeted by six of them — a framework default, a site-wide rule, a component rule, a state rule, and an inline style.

They all apply. Where they set *different* properties, they stack. Where they set the *same* property, one wins.

That contest is what tomorrow is about, and it is the single most useful CSS idea for a tester.
