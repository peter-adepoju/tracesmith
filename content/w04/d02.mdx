The Elements panel is the live DOM, drawn. You have used it since week 2. Today you learn what it can actually do.

## The layout

**Left**: the DOM tree. **Right**: everything about whatever is selected, across several tabs.

- **Styles** — every rule matching this element, winners at the top, losers struck through. Where you spend most of your time.
- **Computed** — the final value of every property, after the whole cascade. The truth.
- **Layout** — grid and flexbox overlays.
- **Event Listeners** — what is listening on this element. Useful for "clicking does nothing".
- **Accessibility** — the computed accessible name and role. Underrated.

## Finding things

**Ctrl+F inside the panel** searches the DOM. It accepts plain text, a CSS selector, or an XPath, which makes it quietly powerful: type `button[disabled]` and it finds every disabled button on the page.

**`$0`** in the Console refers to whatever is selected here. Click an element, switch to Console, type `$0` — no selector needed.

**Scroll into view**: right-click a node in the tree and the browser scrolls the page to it. Useful when you found something by searching and have no idea where it lives.

## Editing live

You can change anything. None of it persists past a reload, which is exactly what makes it safe.

- **Double-click a tag name, attribute or text** to edit it.
- **Right-click → Edit as HTML** to rewrite a whole chunk.
- **In Styles**, click any value and type a new one. Arrow keys nudge numbers, which is the fastest way to find the right spacing.
- **Click the checkbox** beside a declaration to toggle it off and on.
- **`element.style`** at the top of Styles is an empty box for adding your own declarations.

<Callout kind="job">
This turns a complaint into a proposal. Instead of "the button is hard to read", you can write: "contrast is 2.1:1; changing the text colour to `#1b1a17` takes it to 11.4:1 — screenshot attached, tested in DevTools."

A developer can act on the second one immediately. It costs you two minutes and it is the difference between a reporter and a colleague.
</Callout>

## Forcing a state

The `:hov` button in the Styles panel, or right-click → **Force state**. Tick `:hover`, `:focus`, `:active`, `:visited`.

This makes state bugs capturable. A focus outline that is invisible, a hover colour that disappears, a disabled style that looks identical to the enabled one — all of these are awkward to photograph and trivial once the state is pinned.

## The Computed tab

Scroll to the bottom of Styles, or open Computed. It lists the final value of every property.

Three things it is best at:

1. **Settling arguments.** The stylesheet says one thing, the screen shows another; Computed says what the browser actually decided.
2. **Finding the source.** Expand any property and it shows which rule set it, with a link to the file and line.
3. **Checking inheritance.** When a colour comes from three levels up, Computed is where you see it.

## The Accessibility tab

Select an element and open it. It shows the **computed accessible name** — what a screen reader will announce.

This is the fastest possible accessibility check. A button whose accessible name is empty, or is "button", is a finding. An icon-only button with no `aria-label` shows up here immediately, and you have the evidence in one screenshot.

## Breaking on change

Right-click a node → **Break on** → *subtree modifications*, *attribute modifications*, or *node removal*.

The page pauses the moment something changes that node, and the Sources panel shows the code that did it.

You will not use this often. When you do, it is the only way to answer "what keeps resetting this field?" or "why does this element disappear a second after it loads?" — questions that are otherwise nearly unanswerable from the outside.

<Callout kind="watch">
Everything you change here is temporary and local. It does not touch the server, the repository or any other user.

That cuts both ways. It is completely safe to experiment, and it means **a fix tested in DevTools is not a fix**. Be precise in reports: "changing X to Y resolves it locally" is a suggestion, not a resolution.
</Callout>
