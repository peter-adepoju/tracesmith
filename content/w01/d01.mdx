You are about to learn three jobs. Before any of them makes sense, you need one picture in your head: what actually happens between pressing Enter and seeing a page.

Almost every problem you will ever be handed is a problem with one step of that journey. A tester asks "which step broke?". A support engineer asks "whose step was it?". An automation engineer builds something that walks the journey on its own. Same journey, three jobs.

## The journey, in eight steps

You type `example.com/orders` and press Enter.

1. **The browser reads the URL.** It splits it into a scheme (`https`), a host (`example.com`) and a path (`/orders`). The scheme says which language to speak, the host says who to speak to, the path says what to ask for.

2. **It looks up the address.** Computers do not know what `example.com` means. They need a number, an IP address, something like `93.184.216.34`. The system that turns the name into the number is **DNS**, the Domain Name System. Think of it as the phone book.

3. **It opens a connection.** Your computer and the server agree to talk. Over `https` they also agree on encryption, so nobody in between can read what passes.

4. **It sends a request.** This is the important one. The browser sends a short, structured message that says: I would like `GET /orders`, I am this kind of browser, and here is my proof of who I am.

5. **The server does some work.** It checks who you are, reads a database, decides what you are allowed to see.

6. **It sends a response.** Another structured message: a status code saying how it went, some headers, and usually a body — the HTML of the page, or data.

7. **The browser builds the page.** It reads the HTML, and when the HTML mentions a stylesheet, an image or a script, it goes back to step 4 and asks for each of those too. One page is dozens of requests.

8. **The page runs.** Scripts execute, and they make their own requests in the background for data. This is why a page can look finished and still be loading things.

Press play, or step through it one stage at a time. Watch which side of the conversation the work is happening on.

## Why this matters for each job

Say a customer reports: "I click Orders and nothing happens."

A person without this picture can only say "it's broken". A person with it can ask a much better question: **did a request even go out?**

- If no request was sent, the problem is in the browser. Something in step 8 failed before it could ask. That is a front-end problem.
- If a request went out and came back with an error, the problem is on the server. That is a back-end problem.
- If a request went out, came back fine, and the page still shows nothing, the problem is what the page did with a perfectly good answer. Front-end again, but a different kind.

Three different teams, three different fixes. You decided between them in about fifteen seconds, without reading any code, because you knew the journey.

<Callout kind="job">
This is the single most useful habit in technical support: before you form any theory, find out whether the request happened and what came back. In week 4 you will learn to see this directly in the browser. For now, learn the shape.
</Callout>

## One page is many requests

A detail that surprises people: loading one page is not one request. It is often sixty.

The HTML arrives first. It is a document that references other things — a stylesheet, fonts, images, scripts. Each of those is its own request, with its own status code, its own timing, and its own way of failing.

This is why a page can be half-broken. The HTML arrived (status 200, fine) but the stylesheet did not (status 404, missing), so the page renders with no styling. Everything is there, nothing looks right. Once you know a page is many requests, that stops being mysterious.

## Try it for real

You do not need any tools for this one. You need a browser and sixty seconds.

<Callout kind="practice">
Open any website. Press **F12** to open the browser's developer tools, click the **Network** tab, then reload the page.

You will see a list fill up. That list is every request the page made. You are looking directly at steps 4 to 7, happening live.

Do not try to understand the columns yet — that is week 4. Just count the rows. On most sites it is dozens. Sit with the fact that one page is that many conversations.
</Callout>
