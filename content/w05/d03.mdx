Real responses are not flat. A payment response can be two hundred lines deep. Today you learn to walk into one and come out with the value you needed, and nothing else.

## The two moves

Everything is a combination of two steps:

- **Into an object**, by key: `.customer`
- **Into an array**, by position: `[0]`

Chain them and you have a path.

```json
{
  "data": {
    "orders": [
      {
        "reference": "ORDER-1001",
        "customer": { "name": "Ada Obi" },
        "items": [ { "sku": "mer-01", "qty": 2 } ]
      }
    ]
  }
}
```

- `data.orders` — the array of orders
- `data.orders[0]` — the first order
- `data.orders[0].customer.name` — `"Ada Obi"`
- `data.orders[0].items[0].qty` — `2`

Read it left to right as instructions: go into `data`, into `orders`, take the first, into `customer`, take `name`.

<Callout kind="key">
**Arrays start at zero.** The first item is `[0]`, the second is `[1]`.

This causes more confusion in spoken conversation than almost anything else. "The second item" and "item 1" are the same thing, and if you and a developer disagree by one, this is why. Say the path, not the ordinal.
</Callout>

## Describing a shape in words

A skill worth practising, because you will do it in every escalation:

> The response is an object with `status` and `data`. `data` holds `orders`, an array. Each order has a `reference`, a `customer` object, and an `items` array.

That description is what lets someone picture the response without seeing it. Notice it names **types**, not values — the shape is the thing that is stable.

## Where it goes wrong

**Assuming an array has anything in it.** `data.orders[0]` on an empty array is undefined, and code that walks further crashes — which you now recognise as `Cannot read properties of undefined`. An empty list is a normal outcome, not an error, and a surprising number of pages break on it. Always test the no-results case.

**Assuming the order is stable.** Unless the API documents a sort, `[0]` is not reliably the same record twice. If an automated test depends on position, it will be flaky.

**Confusing a single object with an array of one.** `{ "order": {...} }` and `{ "orders": [{...}] }` need different code. An API that returns one shape for a single result and another for several is a genuine design defect, and worth reporting.
