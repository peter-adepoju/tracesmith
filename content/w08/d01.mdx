## Install it

Postman is free for what you need. Download it from postman.com and install the desktop app rather than using the web version, because the desktop app can reach `localhost` and the web one cannot. You will want that from week 13 onwards.

You do not need an account to send requests. Signing in syncs your collections between machines, which is genuinely useful once you have built some.

## Your first request

1. **New** → **HTTP Request**.
2. Method `GET`, URL `https://api.example.test/v1/ping`.
3. **Send**.

That address is the sandbox from this course and is not a real host, so you will get a connection error. That is fine — and it is worth doing, because **recognising a connection failure versus an HTTP error is itself a skill.** A DNS failure means nothing left your machine. A 500 means your request arrived and the server fell over. Completely different problems.

For something real, try:

```
GET https://api.github.com/repos/vercel/next.js
```

That is a public API needing no credentials. You should get a large JSON response and a 200.

## The panes

**Params** — the query string, as a table. Postman builds the `?a=1&b=2` for you, which means it also handles encoding. One less thing to get wrong.

**Authorization** — a structured way to set the credential. Choosing *Bearer Token* and pasting the token adds the right header for you.

**Headers** — everything else. Postman adds some automatically; click *hidden* to see them, because an auto-added header occasionally explains a mystery.

**Body** — for POST, PUT and PATCH. Pick **raw** and **JSON** for most APIs, which sets `Content-Type: application/json` as well. Choosing raw and leaving it as *Text* is a common cause of a 400 that looks inexplicable.

## Reading the response

The bottom half shows the body, and above it three things worth looking at every time:

- **Status** — you know these.
- **Time** — slow is a finding.
- **Size** — a surprisingly large response is a finding too.

The **Headers** tab of the response holds the request id you will quote in escalations.

<Callout kind="key">
Postman is a browser without a page. Same requests, same headers, same responses — and no interface in the way.

That is the whole value. In a browser you test what the page lets you send. In Postman you test **what the server actually accepts**, which is where the interesting defects are. A form that refuses a negative quantity tells you nothing about whether the server does.
</Callout>

The course sandbox runs in your browser rather than on a server, so Postman cannot reach it. Use the inspector for that, and Postman for real APIs — including, from week 13, the ones you are testing at work.
