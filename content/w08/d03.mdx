cURL is the same request as a single line of text. You need it for three reasons: developers paste it at you, DevTools produces it, and a line of text goes in a ticket where a screenshot of Postman does not.

## The shape

```bash
curl -X POST https://api.example.test/v1/payments/initiate \
  -H "Authorization: pk_test_trace_8f41c2" \
  -H "Content-Type: application/json" \
  -d '{"amount":4850000,"currency":"NGN","reference":"ORDER-1001"}'
```

Five flags cover almost everything:

| Flag | Means |
| --- | --- |
| `-X` | The method. Omitted, it is GET — or POST if there is a body |
| `-H` | One header. Repeat for each |
| `-d` | The body |
| `-i` | Include the response headers in the output |
| `-v` | Verbose: show the whole exchange, request included |

The `\` at the end of a line is a continuation — it is all one command.

<Callout kind="watch">
Two traps worth knowing before you run one.

**`-d` without `-X` silently makes it a POST.** So a command that looks like a GET with a body is actually a POST, and will not do what it appears to.

**`-k` disables certificate checking.** It makes a TLS error disappear without fixing anything, and a request sent with it may have been intercepted. If you find `-k` in a command aimed at production, that is a finding — someone silenced a warning rather than investigating it.
</Callout>

## From DevTools to cURL and back

The loop you will use constantly:

1. Reproduce the bug in the browser.
2. **Right-click the request → Copy → Copy as cURL.**
3. Paste it into Postman: **Import → Raw text**. Postman fills in everything.
4. Change one thing, send, see what happens.

That takes a request you could only make by clicking through five screens and makes it something you can send a hundred times with variations. It is how a vague "sometimes checkout fails" becomes "it fails whenever `quantity` exceeds 99".

<Callout kind="key">
Going the other way matters too. Most APIs document their examples in cURL, so being able to read one means being able to use any documentation page — and Postman will import it directly, which saves transcribing by hand and getting a header wrong.
</Callout>

## Running it

On Windows, use **Git Bash** or **WSL**. PowerShell has its own `curl` which is an alias for something else entirely and takes different flags — a confusing half-hour if you do not know.

```bash
curl -i https://api.github.com/repos/vercel/next.js
```

`-i` shows the response headers, which is where the rate-limit information lives on GitHub's API. Worth looking at: `x-ratelimit-remaining` tells you how many calls you have left.
